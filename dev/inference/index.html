Parameter estimation

An estimation problem combines a forward PBM, observations, a measurement likelihood and parameter priors. fit computes a maximum a posteriori (MAP) point using those definitions. Optional local uncertainty and posterior sampling reuse the same physical probability model; neither runs automatically with a basic fit. Declare a physical starting guess, a physical prior, and an explicit transform:

using Distributions: Normal, truncated
ParameterSpec(:g0; initial=0.2,
    prior=truncated(Normal(0.2,0.05),0.0,Inf), transform=LogTransform())

Declared-coordinate convention (inference_map_v2). MAP, local uncertainty and MCMC now use one posterior density in the selected inference coordinates. The physical-prior Jacobian is included once. Transforms are required, including IdentityTransform() for an untransformed parameter. Interim physical_map_v1 MAP/covariance objects cannot be reused; see migration.

A complete first fit

This small synthetic experiment observes total population number during constant-rate removal. Initially the integrated number is 1.5 per unit process volume, and the independent solution is $M_0(t)=1.5\exp(-kt)$. Only k is unknown. Work in the optional environment with Optim and Distributions available:

using PopulationBalanceModels, Optim
using Distributions: LogNormal

grid = Grid1D([0.0,0.5,1.0])
model = PBMModel(removal=Death((x,p,t,ctx)->p.k))
operator = compile(model,grid)
forward_problem = PBMProblem(operator,[1.0,0.5],(0.0,2.0);p=(k=0.3,))

times = [0.5,1.0,2.0]
data = [1.24,1.00,0.68] # synthetic number measurements
measurement = Measurement(times,data,MomentObservable(0);
    likelihood=GaussianLikelihood(sigma=0.03))
parameter = ParameterSpec(:k; initial=0.3, prior=LogNormal(log(0.4), 0.5),
    transform=LogTransform())
experiment = InferenceExperiment(:batch,forward_problem,measurement;dt=0.02)
estimation = EstimationProblem((parameter,),(experiment,))

fitted = fit(estimation;nstarts=2,seed=17)
@assert fitted.converged
estimate = physical_parameters(estimation,fitted.minimizer,:batch)
predicted = vec(only(only(predictions(estimation,fitted.minimizer))))
@assert isapprox(predicted,1.5exp.(-estimate.k .* times);rtol=1e-7)
(removal_rate=estimate.k, predictions=predicted,
 posterior=posterior_components(estimation,fitted.minimizer))
(removal_rate = 0.39694160406799056, predictions = [1.2299755632494973, 1.0085599241272787, 0.6781287470370818], posterior = (loglikelihood = 7.66437852518991, logprior = -0.2259091752622221, logposterior = 7.438469349927688, density_coordinates = :inference, argument_coordinates = :inference, convention = :inference_map_v2))

The Gaussian standard deviation is a declared synthetic observation assumption. initial=0.3 is a starting guess in the same units as the removal coefficient. It is neither a prior mean nor a fixed rate. The standalone forward_problem still has its nominal p.k=0.3; estimation sends each current physical candidate to a remade problem without mutating that base. To match another nominal tuple, write initial=p.k explicitly.

The explicit log transform selects $z=\log k$. The optimizer works in z; kinetics still receive k. MAP is a density mode and depends on those declared coordinates. For a constant likelihood and physical LogNormal(log(0.2),0.5), log coordinates give $\widehat z=\log(0.2)$ and mapped mode 0.2. Identity coordinates instead give the physical-density mode $0.2\exp(-0.5^2)=0.1557601566$. Neither mapped mode is generally the physical posterior mean. Multistart searches do not establish a global optimum.

For a distribution-based physical example, continue with estimating size-dependent growth. The sections below extend the same assembly to shared/local and nuisance parameters, likelihood choices, derivatives, Gauss–Newton, Laplace and MCMC. Deterministic discrepancy and legacy Gaussian calibration are described separately.

Forward models and observations

Transient and stationary problems share observation operators and the statistical model. InferenceExperiment dispatches to simulate or a checked stationary solve; parameter declarations, priors, likelihoods, nuisance parameters, MAP, uncertainty and sampling remain the same.

Forward modelMeasurement declarationSensitivity path
Transient sectional, exact-moment and differentiable coupled modelsMeasurement(times, data, observable; likelihood)Native ForwardDiff; optional continuous ODE sensitivities for eligible residual solvers
Transient tensor, axial and eligible complete transport updatesSame timed declaration; select the actual forward solverForwardDiff where supported, or explicitly selected finite differences
Stationary sectional, exact-moment, tensor, coupled and axial residualsMeasurement(data, observable; likelihood)Implicit equilibrium sensitivities for smooth isolated roots
Quadrature/assumed-shape moments and other AD-incompatible residualsSame declaration for the relevant problemExplicit finite differences, with resolved perturbed solves and unchanged closure

This is support for fitting eligible forward models, not every combination of observable, closure, boundary policy and integrator. A moment model does not automatically predict a PSD; a complete HOC/characteristic time update does not define a stationary residual. Rank changes, branch changes and extinction events do not acquire differentiable sensitivities merely by entering estimation.

observe(observable, solution) evaluates native transient or converged stationary results directly. CellObservable(observable, cell) selects a local axial state, including named populations and bulk variables. Global reactor inventories need an explicit FunctionObservable with the appropriate cell-volume weighting.

For stationary measurements, a vector is one output column; matrix columns are repeat measurements of one equilibrium. Distinct operating points use separate experiments, which may share kinetic parameters. StationarySolver accepts the NonlinearSolve algorithm and solve tolerances and uses no artificial observation times or timesteps. Its implicit derivative solves the linearized equilibrium equations, including constraints and bulk exchange, rather than differentiating Newton's iterations. Singular/ill-conditioned state Jacobians reject that path; there is no automatic regularization. See stationary estimation for a complete synthetic crystallizer example and the dense-factorization limitation.

The legacy CalibrationProblem accepts Observation(data, observable) for stationary Gaussian calibration and timeless ResidualObservation or WassersteinObservation(x, F, population; ...) blocks for deterministic fitting. Their statistical meanings are unchanged. No solver failure is a valid fit.

Describe the measurements

An observation operator maps a solved PBM state to predicted measurements. MomentObservable, BulkObservable, FunctionObservable and SystemObservable can all be used in a Measurement.

Other instruments produce histograms or bulk measurements. For a sectional distribution, DistributionObservable integrates over the measurement bins:

histogram = DistributionObservable(measured_edges;
    coordinate=:length, population=:crystals, weight=L->1.0)
sizes = Measurement(times, counts, histogram;
    likelihood=MultinomialLikelihood(), source=:particle_counter)
concentration = Measurement(times, measured_concentration, BulkObservable(:c);
    likelihood=GaussianLikelihood(sigma=(theta,experiment)->theta.noise),
    source=:concentration_instrument)

Data matrices have one output per row and one time per column. Each experiment solves at the union of its measurement times. The likelihood sums all bins, times, and experiments; it is never divided by the number of observations.

The coordinate must agree with the model. Diameter and volume densities differ by a change-of-variable Jacobian. Weighting is also explicit: number uses L->1.0, volume can use L->π*L^3/6, and the nanoparticle scattering approximation uses L->L^6. Bin values are integrals, not density values sampled at centres. Weighted sectional integrals use eight-point Gauss quadrature of the piecewise-constant solver density.

A response callback response(lo,hi,L,p,t) can supply the probability that a particle of true size L is detected in a measured bin. This is the hook for sizing uncertainty and detection efficiency. Its probabilities must be finite and between zero and one. Resolve discontinuities explicitly; quadrature through an unresolved detection threshold is another numerical approximation.

Moment states can predict compatible moments and explicit observation integrals. A histogram requires an independently specified reconstruction, supplied through a custom observable. QMOM nodes and weights are quadrature data; they are not automatically a uniquely determined measured PSD.

Choose the likelihood

The choice follows how the instrument produced the data.

DataLikelihoodInterpretation
Actual particle counts in bins, with a sampled total at each timeMultinomialLikelihood()Conditional size probabilities in the measurement window
Absolute counts from a known sampled volume or exposurePoissonLikelihood(exposure=...)Expected counts equal predicted bin concentration times exposure
Suitable continuous outputsGaussianLikelihood(sigma=...) or covariance=...Absolute errors or an explicitly fitted noise model
Nonnegative continuous measurementsTruncatedGaussianLikelihood(sigma=...,lower=0)Independent Gaussian measurements conditioned above the specified lower bound; not a clipping model
Normalized continuous fractionsGaussianLikelihood with independent contrastsContinuous instrument fractions, without an invented particle count

For sampled counts $y_i$, let $N=\sum_i y_i$ and normalize the predicted bin integrals to probabilities $p_i$ over the stated window. The multinomial contribution is

\[\log p(\boldsymbol y\mid\theta) =\log(N!)-\sum_i\log(y_i!)+\sum_i y_i\log p_i(\theta).\]

The measured total supplies the statistical sample size. Twice as many sampled particles generally supplies more information. A normalized instrument trace does not supply that count, and must not be multiplied by an arbitrary N. Zero counts are valid. A nonzero count in a zero-probability bin has zero likelihood.

For absolute Poisson counts, the contribution retains both $y_i\log\lambda_i-\lambda_i$ and the factorial normalization. For Gaussian outputs with covariance $\Sigma(\theta)$,

\[\log p(\boldsymbol y\mid\theta) =-\frac12[\widehat{\boldsymbol y}(\theta)-\boldsymbol y]^\mathsf T \Sigma(\theta)^{-1}[\widehat{\boldsymbol y}(\theta)-\boldsymbol y] -\frac12\log\det\Sigma(\theta)-\frac n2\log(2\pi).\]

The determinant is essential when noise parameters are inferred. Covariance may be a fixed matrix or (theta,experiment)->matrix and applies to vec(data): outputs within a time, then successive times.

For independent truncated-Gaussian measurements with lower bound zero, retain the normalization for every observation:

\[\log p(y_i\mid\theta) =-\frac{[y_i-\mu_i(\theta)]^2}{2\sigma_i^2} -\log\sigma_i-\frac12\log(2\pi) -\log\Phi\!\left(\frac{\mu_i(\theta)}{\sigma_i}\right),\qquad y_i\ge0.\]

The location $\mu_i$ is the model's latent prediction; the conditional measurement mean differs near zero. sigma may be fixed or a (theta,experiment)->scales callback. Correlated truncation is not implemented. Use this likelihood when measurements follow that model; censored instruments and clipped outputs require different likelihoods.

Normalized fractions have a sum constraint. Supply a full-row-rank contrast matrix A with $A\boldsymbol1=0$ and their covariance:

fractions = Measurement(times, fractions_data,
    DistributionObservable(edges; coordinate=:length, normalize=true);
    likelihood=GaussianLikelihood(covariance=Sigma, contrasts=A))

The likelihood projects data, predictions and covariance before factorization. It does not invert the singular full covariance or add a diagonal ridge. Predictive outputs from this likelihood are also in contrast coordinates. The Gaussian contrast model is an unbounded approximation. Choose it where noise outside the physical simplex is negligible; bounded-simplex measurements need a different response/likelihood model. Declared normalized fractions and post-response predictions must lie in $[0,1]$ and sum to one at every time (absolute normalization tolerance $10^{-10}$). Invalid data are rejected; they are never renormalized or clipped.

If moments were calculated from the measured histogram, they share its measurement errors. Use the histogram alone, or a joint vector observable with the appropriate joint covariance; do not count both as independent evidence. Use the same source tag on dependent blocks: InferenceExperiment rejects duplicate tags. Untagged dependence cannot be inferred automatically.

Declare fitted and fixed parameters

Each scalar declaration supplies a physical starting guess, a physical prior, and an explicit transformation. Different parameters can use different transforms:

using Distributions: Normal, LogNormal, truncated
g0 = ParameterSpec(:g0; initial=0.2,
    prior=truncated(Normal(0.2,0.05),0.0,Inf), transform=LogTransform())
offset = ParameterSpec(:offset; initial=0.0,
    prior=Normal(0,0.1), transform=IdentityTransform(), role=:nuisance)

Nuisance parameters enter the joint posterior and covariance. Known values belong in fixed tuples, not in ParameterSpec. Priors must be proper continuous univariate Distributions.jl distributions; this interface has no implicit improper prior or multivariate prior declaration.

Explicit transformPhysical range
IdentityTransform()Entire real line; prior rejects outside its support
LogTransform()Positive half-line
LogitTransform(lower,upper)Interior of a finite interval
ShiftedLogTransform(bound; upper=false/true)Lower/upper open half-line

A transform may cover more than the prior support, but cannot silently remove allowed support. An unrestricted Normal is incompatible with a log transform: truncate it explicitly when positivity is part of the belief. For a Normal belief about log(g0), use the equivalent physical LogNormal prior. No prior family is silently changed and no transform is selected automatically.

Starting values must be finite, in prior support, and representable by the transform. They are never clamped. Known interval supports are checked directly; for custom/disconnected supports, compatibility of a custom transform remains a caller declaration. Physical constraints are checked on each candidate and do not establish regularity of an arbitrary boundary optimum.

parameterization(estimation) # physical initials/priors, scopes and explicit transforms

A shared parameter has no experiment name. Add experiment=:batch_B to make a fitted parameter local to that experiment. Put known values in the problem's fixed tuple or the experiment's fixed tuple. A name cannot be fixed and fitted, or shadow a shared parameter locally.

An experiment's setup callback constructs its actual initial-value problem:

setup = function (theta, base)
    u0 = copy(base.u0)
    population(base,u0,:crystals) .*= theta.initial_scale
    remake(base; u0, p=theta)
end
experiment = InferenceExperiment(:batch, base_problem, sizes, concentration;
    setup, dt=0.002)
problem = EstimationProblem(parameters, (experiment,); fixed=(known_value=1.0,))

This permits uncertain initial populations, bulk initial states, calibration factors and noise parameters. A Measurement response callback (prediction,theta,experiment)->... can apply a calibration factor. Operating histories remain in the physical problem or are rebuilt by setup. The default setup merges physical parameters into a NamedTuple p.

Fit the posterior mode

Load Optim in a working environment. For a constructed EstimationProblem:

using Optim
result = fit(problem) # MAP by default, starting from ParameterSpec initial values
result.parameters
result.diagnostics.gradient_norm

result = fit(problem; nstarts=3, seed=22, scaling=ones(length(problem.parameters)))
# Or supply explicit inference-coordinate vectors:
result = fit(problem; starts=[z_start_1,z_start_2])

The default is BFGS with ForwardDiff derivatives of the shared posterior. The supplied scaling affects optimizer work coordinates, not the declared z-density. Convergence checks z-stationarity (diagnostics.stationarity); physical-posterior stationarity is not required. Gradients retain their argument coordinate labels. Nonfinite, saturated or unsupported transform states are rejected. Boundary/nonregular modes of the declared z-density do not acquire an ordinary Gaussian covariance merely through a small numerical gradient. A seeded perturbation generates extra starts. Multiple starts improve exploration but do not establish a global optimum.

The selected gradient is checked against step-halved central differences before fitting and sampling. Those differences verify the derivative; they are not the default optimizer or NUTS gradient. Limiters can produce nonsmooth objectives; a local derivative check does not establish global smoothness.

Results retain separate likelihood/prior contributions, convergence, gradients, objective history, start outcomes, instrumented forward-solve counts and timing. NumericalFailure rejects an evaluation and records a message. Programming errors propagate. An external solver must check its success code and return exactly the requested output times. Invalid derivatives are reported rather than replaced silently with finite differences.

Choose how derivatives are calculated

EstimationProblem(...;derivatives=:auto) and the legacy CalibrationProblem use ForwardDiff by default. This propagates parameter derivatives through the actual calculation, including transforms, the appropriate target-specific prior terms, observation responses and inferred noise. For a small parameter vector it usually requires one dual-number solve per experiment, rather than two perturbed solves per parameter. Larger vectors are processed in ForwardDiff chunks. Evaluation counts describe these solves, not the number of underlying arithmetic operations.

posterior_gradient(problem,z) # common z-density gradient, including prior Jacobians
likelihood_gradient(problem,z) # excludes prior AND density-transform penalties
check_gradient(problem,z)
result.diagnostics.derivative_backend
result.diagnostics.gradient_evaluations
result.diagnostics.forward_solves

Callbacks must preserve their numeric input types: use similar(u) or zeros(eltype(u),...) for state-dependent storage, and avoid converting fitted values to Float64. See ForwardDiff's limitations. AD has been checked for the analytical growth observable, native sectional growth/removal, exactly closed moments, and coupled bulk balances. A fixed grid is important. The Inguva fitting recipe rebuilds a mesh whose number of cells can change with parameters; it explicitly requests finite differences. Eigen-based QMOM inversion is also outside the verified AD path. Select derivatives=:finite_difference for such a calculation and inspect step-size checks. An incompatible AD callback raises DifferentiationFailure.

For a differentiable ODE residual, the optional adapter instead integrates continuous forward sensitivities or an interpolating adjoint:

import SciMLBase
using SciMLSensitivity, OrdinaryDiffEqTsit5
solver = SciMLSensitivitySolver(Tsit5();sensitivity=:auto,
    reltol=1e-8,abstol=1e-10)
experiment = InferenceExperiment(:batch,physical_problem,measurements...;
    setup,solver)
problem = EstimationProblem(parameters,(experiment,))

Install these optional packages in the working environment. SciMLSensitivity loads ReverseDiff, which the adapter uses for the scalar likelihood's state gradient. No sensitivity packages are loaded for a native fit. The automatic rule chooses forward sensitivities for at most 16 fitted coordinates and the adjoint otherwise. This is a starting heuristic, not a cost guarantee; choose sensitivity=:forward or :adjoint and compare timings for the actual problem. Both include parameter-dependent initial states, shared and experiment-specific parameters, and direct observation/noise dependence. Correlations across measurement times enter one joint likelihood.

Forward sensitivities integrate $\partial u/\partial z$ alongside the state. The adjoint retains a dense forward trajectory, then integrates backward with measurement contributions. It avoids an augmented state for every parameter, but the current adapter forms local residual Jacobians and retains the trajectory; it is not a memory-free or matrix-free implementation. Tighten solver tolerances and check gradients when changing the residual or integrator. ODE adapters do not enforce the native CFL or positivity stage checks. Event callbacks are rejected because sensitivity jump rules are not implemented; prescribed time histories can use fixed tstops instead. Direct cell-shift methods are not ODE residuals and cannot use this adapter.

This uses the direct forward and direct adjoint interfaces. Merely adding sensealg to an ODE solve differentiated with ForwardDiff does not select an adjoint. The adapter explicitly invokes the sensitivity equations while reusing the package's likelihood.

Request sensitivity-based uncertainty

For fixed-error Gaussian measurements, a useful first calculation is a local Gauss–Newton approximation at the MAP:

using PopulationBalanceModels, Optim
result = fit(problem) # MAP only; the statistical target is unchanged
local_gaussian = gauss_newton_approximation(problem,result)
# Equivalent opt-in convenience:
result = fit(problem; uncertainty=:gauss_newton)
kinetics = marginal_covariance(problem,local_gaussian; role=:kinetic)
draws = parameter_draws(problem,local_gaussian; n=1000,seed=23)

Let $r(\theta)$ contain all observation residuals after covariance whitening and any independent contrasts. The response, times, experiments, parameter sharing and uncertain initial conditions are the same as in the likelihood. Then

\[J_z=\left.\frac{\partial r(T(z))}{\partial z}\right|_{\widehat z},\qquad P_{\mathrm{GN}}=J_z^\mathsf TJ_z+ \left.\frac{\partial^2[-\log\pi_z(z)]}{\partial z\,\partial z^\mathsf T} \right|_{\widehat z},\qquad \Sigma_{\mathrm{GN}}=P_{\mathrm{GN}}^{-1}.\]

This is a Gaussian in declared inference coordinates. The full transformed prior density is $\pi_z(z)=\pi_\theta(T(z))|\det DT(z)|$ for ordinary physical priors. A physical Normal is generally not Normal in z. No averaging over bins/times or residual-based noise rescaling is introduced. Factorizations and solves produce the covariance. A kinetic marginal uses the relevant block of the full joint covariance, including calibration and initial-state nuisance parameters; it does not fix those parameters at their MAP values. The Ceres covariance guide explains the measurement-weighted sensitivity construction for least squares; the prior term above extends that local construction to this declared posterior.

Initial support is GaussianLikelihood with fixed scalar/array standard deviations or fixed covariance matrices, including projected fraction covariance. Noise callbacks, inferred covariance, count likelihoods and truncated Gaussians are rejected explicitly: their information cannot be obtained just by weighting the mean-prediction Jacobian. Use full-posterior Laplace or MCMC for those targets. The legacy deterministic discrepancy blocks are not statistical uncertainties.

ForwardDiff computes prediction Jacobians by default. The independently step-halved checks also verify prior curvature and the assembled precision in its covariance-scaled directions, so a large error confined to a strong direction is not confused with unresolved weak curvature. An information discrepancy $e<1$ bounds the checked candidate covariances between $C_{\mathrm{GN}}/(1+e)$ and $C_{\mathrm{GN}}/(1-e)$. This checks derivatives of the chosen discrete model, not continuum accuracy or the omitted Hessian terms. Grid, domain and time refinement remain separate checks. Independent residual/prior gradients are also checked in the covariance metric; small Jacobian errors are not allowed to hide cancellation in $J^\mathsf Tr$ near the mode. These checks do not rescale errors by the observed residual size.

GaussNewtonFailure.report records nonstationarity, unresolved sensitivities, nonpositive precision or excessive conditioning. No ridge or pseudoinverse inserts apparent certainty. Data rank and prior curvature are reported separately: a proper prior can support a data-null direction without making it identified by measurements. An external solver must support the prediction Jacobian's AD path. This does not convert an adjoint scalar-gradient callback into a prediction Jacobian; derivatives=:finite_difference is an explicit alternative, subject to the same checks.

Parameter draws cost no PBM solves. A joint Gaussian is drawn in z and every sample is transformed to physical values (theta and physical). The raw z samples remain available, including those whose transforms overflow or whose physical values violate the prior/constraints. in_support and transform_valid flag failures. No draw is clipped, filtered, resampled or silently truncated. A mapped Gaussian is generally not a physical Gaussian, and a mapped MAP is not the physical posterior mean. posterior_predictive still needs its explicit solve budget. Label resulting intervals Gauss–Newton approximations. The construction omits $\sum_i r_i\nabla^2r_i$ from the full posterior Hessian; it need not capture bounds, curved compensation, multiple basins or systematic model error. Positive information and optimizer convergence also do not independently certify a minimum of the full posterior.

Request full-Hessian Laplace uncertainty

laplace = laplace_approximation(problem,result)
# Equivalent opt-in convenience:
result = fit(problem; uncertainty=:laplace)
kinetics = marginal_covariance(problem,laplace; role=:kinetic)
draws = parameter_draws(problem,laplace; n=1000,seed=23)

The Hessian uses nested ForwardDiff on the actual negative log posterior. Independent step-halved differences of its AD gradient verify the curvature:

\[H_z=\left.\frac{\partial^2[-\ell_z(z)]}{\partial z\,\partial z^\mathsf T} \right|_{\widehat z},\qquad p_z(z\mid y)\approx\mathcal N(\widehat z,H_z^{-1}).\]

All nuisance parameters enter this joint curvature. A kinetic marginal uses the corresponding block of the full covariance; inverting the kinetic Hessian subblock would instead condition on fixed nuisance parameters. With a SciML sensitivity adapter, this second derivative passes through the primal ODE solve; it does not differentiate a first-order adjoint. An explicitly selected finite-difference backend also uses finite-difference curvature.

Factorizations and solves form the covariance and draws. Nonconvergence, nonstationarity, unstable derivatives, nonpositive curvature or excessive conditioning reject the approximation with a LaplaceFailure report. No regularization converts an invalid Hessian into reported certainty. Positive local curvature does not establish unimodality or Gaussian tails. Centers, Hessians, covariances and marginal blocks use the declared z units. Physical summaries come from transforming joint Gaussian draws, with explicit validity flags. Intervals are labelled local Laplace approximations; positive curvature does not prove global Gaussian shape. Predictive propagation reports invalid draws as failures rather than conditioning silently on successful draws.

Sample the same posterior

Sampling is requested separately and requires AdvancedHMC and MCMCDiagnosticTools in the working environment. Continuing the first fit above:

using AdvancedHMC, MCMCDiagnosticTools
samples = sample_posterior(estimation; initial=fitted,
    chains=4, warmup=500, seed=24, verbose=true)
report = diagnostics(samples)
(report.stopping_reason, report.samples, report.diagnostics_passed)
report.check_history

The default warms up each of four chains once, freezes adaptation, then continues those same chains in batches of 250 retained draws. Checks use all retained chains jointly. After at least 500 draws per chain, two successive checkpoints must pass rank-normalized split R-hat ≤ 1.01, bulk and tail ESS ≥ 400, BFMI ≥ 0.3, finite mean MCSE, and zero retained divergences or maximum-depth hits. There is a finite budget of 10,000 draws per chain. Set min_samples, batch_samples, max_samples and consecutive_passes to change this policy. These are draw budgets, not limits on elapsed time or PBM evaluations.

stopping_reason records :diagnostics_passed, :max_samples or :sampler_pathology. Exhausting the budget without the required consecutive passes returns diagnostics_passed=false. A retained divergence or depth hit ends diagnostic mode unsuccessfully: appending draws cannot undo that event. The draws and failed checks remain available; the adapter does not discard them or restart adaptation. Inspect the diagnostics and change tuning deliberately before starting a new run. Warmup divergences are reported separately.

For an explicitly fixed run, supply a count:

samples = sample_posterior(estimation; initial=fitted,
    stopping=:fixed, samples=1000, chains=4, warmup=500, seed=24)

Existing calls with samples=N also select fixed mode and retain that sampling policy. The Jacobian-corrected target represents the same physical posterior; bitwise transition sequences across code changes are not promised. They report diagnostics but do not stop early. Fixed mode allows one chain; diagnostic stopping requires at least two. Four dispersed chains are a useful default, especially when different plausible modes need to be explored. Joint chains are currently advanced serially. Batching preserves the adapted kernel, phase point and private RNG; it is not a persistent checkpoint/restart format.

R-hat and ESS assess mixing, not a specified accuracy for every reported quantity. Optionally monitor cheap scalar functions of physical parameters and require absolute Monte Carlo precision:

samples = sample_posterior(estimation; initial=fitted, seed=24,
    diagnostic_quantities=(rate=theta -> theta.shared.k,),
    mcse_limits=(rate=(mean=0.005, quantiles=(0.025=>0.01, 0.975=>0.01)),))
diagnostics(samples).quantity_diagnostics.rate

These functions receive (shared, experiments) and must return deterministic, finite real scalars without additional PBM solves. Every monitored quantity also enters the R-hat/ESS screen. MCSE limits have the quantity's units; quantile MCSE measures uncertainty in an estimated interval endpoint, not the posterior interval width. Constant or unresolved diagnostics cannot pass. Repeated checks are a computational stopping rule, not proof of global mixing, a rigorous sequential-coverage guarantee, identifiability or model adequacy. Inspect traces and posterior shape before interpreting intervals.

NUTS and MAP use the same logposterior and gradient; sampling_logposterior is a compatibility alias. A supplied laplace covariance already uses z and is consumed directly for initialization. An auxiliary sampling map converts it locally into sampler coordinates for tuning only. This conversion is not a new posterior covariance estimate. Otherwise adaptation is diagonal by default. An explicit positive-definite initial_covariance also selects dense adaptation. It is tuning, not a verified uncertainty estimate. Supply one matrix or a tuple/vector of matrices for different chain starts. A Laplace approximation can also inform dispersed starts; explicit inference-coordinate starts are accepted. Warmup draws are excluded from retained diagnostics.

The report retains warmup and post-warmup statistics, acceptance rates, adapted inverse masses, step sizes, divergences, depth hits, gradient checks, seeds, backend versions, evaluation counts and elapsed time. mcse_mean concerns inference-coordinate means. Use diagnostic_quantities for physical-coordinate precision. diagnostics(z, statistics; ...) can reassess existing draws with the same joint screen; it does not apply the controller's minimum-length or consecutive-pass rules.

Strongly correlated parameters can benefit from a bijective sampling_map with to_sampler, from_sampler, logabsdetjac and label fields. Here logabsdetjac(y) is the log absolute determinant of from_sampler at y. The adapter samples $\log p_z(\mathrm{from\_sampler}(y))+\log|\det J_{\mathrm{from\_sampler}}(y)|$. The inverse and determinant are checked at every mapped target evaluation. check_sampling_map(problem,map,z) also checks both inverse directions and the transformed gradient at a supplied point in the original posterior support. Use it at representative points and tails. The step argument controls the independent finite-difference verification stencil; check its halving where limiter switches or sharp likelihood curvature affect the comparison. Finite tests cannot prove that arbitrary callbacks are globally bijective or cover the whole posterior support; that remains a requirement of the supplied map. The prior probability laws remain unchanged. Returned z draws and statistics.log_density refer to the internal-coordinate sampling density, including the parameter-transform Jacobian exactly once. sampler_log_density also includes the auxiliary-map Jacobian. A tuning matrix supplied with a map must be expressed in sampler coordinates. AdvancedHMC's DenseEuclideanMetric takes the inverse mass matrix: a supplied initial_covariance initializes that matrix, following its metric convention. Hamiltonian energies, BFMI and transition statistics remain those of the sampler coordinates, including the map Jacobian. They are not relabelled as inference-coordinate energies or covariance estimates. The protein tutorial uses a unit-determinant growth-rate shear for its three-/four-parameter targets with fixed interfacial energy. Earlier four-/five-parameter targets used different nonlinear maps and are preserved as historical results. Archived recipes have different statistical targets; their inputs and producing records are retained with the historical fixtures.

See the upstream AdvancedHMC and MCMCDiagnosticTools documentation for sampler and diagnostic definitions. NUTS reuses the selected AD or ODE-sensitivity backend and adds the required coordinate-Jacobian gradient; diagnostics record the target and backend.

The growth-estimation case compares priors, Laplace intervals and NUTS draws for synthetic density measurements. The protein case illustrates coefficient– exponent tradeoffs and predictive mismatch despite a passed sampling screen.

MCMC parameter_draws also returns indices into reshape(samples.z, number_of_parameters, :), with draws varying before chains. Retain these identities when exporting predictive curves. A seed alone need not reproduce randperm selection across Julia versions; the historical protein example exports posterior_predictive_indices.csv for that purpose. Sampling tuning matrices and transformed Hamiltonian energies retain their separate meanings.

Keep the density coordinates explicit

Ordinary priors always describe the physical parameter passed to the PBM. Let $\theta=T(z)$. MAP, gradients, local uncertainty and MCMC share

\[\ell_z(z)=\sum_{e,b}\log L_{e,b}(T(z)) +\sum_j\left[\log\pi_j(T_j(z_j))+\log|T_j'(z_j)|\right].\]

Each ParameterSpec contributes once across all experiments and measurement blocks. With an auxiliary $z=S(y)$, sampling adds only $\log|\det DS(y)|$. This auxiliary map does not change the MAP target. Likelihood-only diagnostics contain neither prior penalties nor transform Jacobians.

A custom gradient(z) supplies the common z-density derivative. The legacy gradient_target=:physical contract means the derivative of the physical-density objective with respect to z; the package adds its log-Jacobian gradient once. :sampling aliases the common target. Independent finite differences verify these contracts. coordinates describes function arguments, not a choice of posterior probability law or a second MAP convention.

Migration and retained results

  • Every ParameterSpec now requires a transform, including IdentityTransform(). There is no automatic selection. initial is still a physical guess; use initial_coordinates(problem) for internal optimizer starts.
  • Pass physical distributions directly. Prior(d; coordinates=:physical) remains equivalent for compatibility. Legacy tagged inference priors retain their original z-law and receive no additional parameter Jacobian. A Normal law for log(g0) can be written as a physical LogNormal in new code.
  • Results carry inference_map_v2. Interim physical_map_v1 and older/unversioned MAP and local-Gaussian objects require recomputation. They cannot be relabelled or silently used as sampler covariance. Nonlinear changes of declared coordinates may change MAP and local Gaussian approximations.
  • Existing MCMC draws can remain valid when the physical posterior law is unchanged. Their saved transforms, producer manifests and compatibility records remain necessary; this change alone is not a replay receipt.
  • Retained growth/protein figures and tables remain historical under their producer conventions. No production fits or long posterior chains were rerun. Current scripts write versioned metadata and protect existing outputs; use separate output directories for a new calculation.

Check prediction, identifiability and numerical error

Numerical-refinement and prior-sensitivity comparisons retain data, times, likelihood settings, fixed parameters, constraints and measurement responses. Changing a noise scale is a statistical-model change, not numerical refinement. The checks cannot establish that arbitrary model/setup callbacks describe the same physical initial conditions or observable; keep those definitions fixed when changing the solver, grid or domain.

Drawing approximate parameters does not solve the PBM. Predictive propagation has an explicit forward-solve budget:

draws = parameter_draws(problem,samples; n=40,seed=25)
prediction = posterior_predictive(problem,draws;
    max_solves=40, measurement_noise=true, seed=26)

One experiment per draw requires one solve; additional experiments multiply the cost. The budget is checked before execution. Returned blocks separate raw model outputs, latent measurement means and fresh measurement noise. Failures remain visible by draw. Poisson predictions include known exposure; multinomial predictive counts condition on the observed snapshot totals.

identifiability_report separates likelihood prediction sensitivities and observed likelihood curvature from physical-prior curvature. By default its parameter derivatives use z; coordinates=:physical changes those derivative arguments explicitly. Prediction rank uses the unscaled measurement units and omits noise-only information; inferred noise also enters the likelihood Hessian. These are local diagnostics, not proof of structural identifiability.

likelihood = estimation_profile(problem,result,index,values; target=:likelihood)
posterior  = estimation_profile(problem,result,index,values; target=:posterior)

Each profile reoptimizes every remaining coordinate, including nuisances. The likelihood profile obtains its own unpenalized reference optimum. Posterior profiles describe declared-coordinate posterior density shape (their supplied profile grid still uses internal coordinates) and have no ordinary likelihood-confidence threshold. Check every conditional convergence flag.

replacepriors retains the physical experiment and changes explicit prior declarations. priorsensitivity fits named alternatives and reports mode shifts in reference posterior SD units and changes in Laplace uncertainty. Its prior_sensitive flag uses explicit, configurable shift/scale-ratio thresholds; it is a screening rule, not an identifiability theorem. Prior dependence is evidence to examine, even when MAP is stable.

For the growth study, the residuals below apply the fitted truncated-Gaussian CDF to each measurement, then the inverse standard-normal CDF. This accounts for the asymmetric errors near zero density. The quantile plot compares these normal quantile residuals with a standard Gaussian. The final panel shows how much the rate estimates change when lognormal priors are replaced by uniform priors.

refinement_study refits explicitly named numerical variants. Keep measurements, parameter coordinates and priors consistent. Compare spatial resolution, size domain and time step separately; compare moment closures separately again, because closure error is a model approximation. The growth case study records such refits alongside reference posterior uncertainty. Parameter uncertainty, measurement noise, numerical error and physical model inadequacy remain different sources of discrepancy.

The growth example refits with Inguva2022 and MUSCL. The first method requires a matched travel-time mesh and time step, so they must be refined together. The MUSCL checks refine space, time and domain separately. The analytical solution supplies the reference; interpolating bin averages to point density measurements adds a separate observation-reconstruction error.

Existing Gaussian calibration interface

A deterministic comparison is available when no probabilistic observation model is declared. ResidualObservation contributes weight * mean(((prediction-data)/scale).^2); WassersteinObservation integrates squared differences between conditional number quantiles. The comparison scales are not sensor standard deviations. These blocks use CalibrationProblem and the optional Optim extension, but cannot be mixed with Gaussian observations or used to manufacture confidence intervals. loss_contributions separates their contributions; sensitivity_report reports local sensitivity rank without a covariance estimate.

CalibrationProblem, Observation, Experiment and fit(calibration,z0) remain available for existing code. With Observation blocks they implement the Gaussian maximum likelihood workflow. ResidualObservation instead selects the explicit deterministic discrepancy described above. confidence_ellipsoid is the Gaussian workflow's local frequentist calculation and rejects discrepancy weights. It is separate from the Bayesian Laplace API. The older small kinetic examples remain regression examples. New Bayesian work should use EstimationProblem so all inference methods share priors, transforms and likelihood definitions.
