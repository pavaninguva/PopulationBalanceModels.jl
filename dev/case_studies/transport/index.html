Two-coordinate transport

Physical question and implementation

A joint distribution over two internal properties can advect at different speeds in each direction. This case isolates transport from nucleation and process coupling so analytical bin averages can distinguish numerical error from model uncertainty. Run examples/two_coordinate_transport.jl. It compares a smooth profile and a rectangle on 32, 64, and 128 bins per axis.

The general Grid2D residual supports growth, midpoint birth/removal, bilinear point deposition, and midpoint distributed creation. Boundary influx has units of number flux per tangential internal coordinate and is integrated over the face width. The per-term 2D GaussianInjection regularizes a point using tensor bin fractions; the GaussianNucleation physical constructor is 1D. 2D collisions, general integrated-source terms, and coupled 2D system blocks are unsupported. These restrictions are separate from the narrower eligibility of the direct methods below.

Compact/ADI equations and paper fidelity

Li et al., Particuology 110 (2026), 310–319, DOI 10.1016/j.partic.2026.01.024, is the HOC–ADI reference paper. The inherited paper assessment records unresolved issues that prevent claiming a faithful reproduction:

  • Eq. 1 uses separate g1 and g2, but Eqs. 6–15 contain g1*g2 multiplying both directional derivatives. Used literally as the leading transport coefficient, that does not recover Eq. 1 for independently chosen velocities.
  • The compact coefficients a1–a5 and important derivation details are left to supplementary data. Those supplementary coefficients are not available to this implementation. The printed time levels/intermediate updates are also ambiguous.
  • In the stated Case 1, g1=g2=0.2, the domain is [0,2]² and t=100. Under zero incoming flux the Gaussian center would move from (0.4,0.4) to (20.4,20.4), outside the domain. Units, horizon or boundary conventions need clarification before reproducing its reported nonzero final distributions.

These are reproducibility observations about the supplied equations, not a claim that no corrected author implementation exists. A literal paper backend remains pending supplementary equations or author code.

HOCADI(time_order=4) instead implements the following fully specified, independently tested compact/ADI variant for homogeneous constant growth:

\[\tfrac14 d_{i-1}+d_i+\tfrac14 d_{i+1} =\tfrac{3}{4h}(f_{i+1}-f_{i-1}),\qquad Md=Df.\]

For each direction with speed g, the Cayley update is

\[(M+\tfrac{g\Delta t}{2}D)f^{new} =(M-\tfrac{g\Delta t}{2}D)f^{old}.\]

Taking one x solve and one y solve defines S₂(Δt). The tensor operators commute in this restricted problem. time_order=2 uses S₂ directly. time_order=4 uses

\[S_4(\Delta t)=S_2(\gamma\Delta t) S_2((1-2\gamma)\Delta t)S_2(\gamma\Delta t),\quad \gamma=(2-2^{1/3})^{-1}.\]

This fourth-order composition has a negative middle substep. It is restricted to reversible, homogeneous autonomous transport here. No birth, death, aggregation, breakage or bulk coupling is silently run backward. Periodic uniform axes are required; one-sided physical compact closures remain work. The spatial derivative is fourth order, and independent tests isolate second- and fourth-order temporal convergence against the exact semidiscrete Fourier solution. Cyclic tridiagonal LU plus rank-two correction gives O(nx*ny) work per directional sweep. Linear L2 stability does not establish positivity.

The 2D comparison

Run julia --project=. examples/two_coordinate_transport.jl. Results and environment metadata are under docs/src/assets/; the script has no plotting dependency.

The shared PDE is

\[\partial_t n+0.5\partial_xn+0.25\partial_yn=0, \quad (x,y)\in[0,1]\times[0,0.5],\quad t_f=0.25,\]

with periodic diagnostic boundaries. Smooth separable Fourier densities have analytical bin averages. A rectangular pulse separately tests discontinuous fronts. All methods use identical bin-integrated initial numbers, grids, output times and analytical references. Uniform averages themselves satisfy the constant-advection PDE, allowing the compact derivative and exact shifts to evolve the same representation without a nodal/average comparison error.

MethodSpatial/evolution treatmentEligibility
WENO5 + SSPRK(3,3)Unsplit conservative FV residual, summed CFL 0.4Current general 2D growth/source residual
HOCADI4_variantCompact derivative plus composed directional implicit solves; directional CFL 1Constant homogeneous growth, periodic uniform axes
InguvaBraatzconstantshiftCommuting directional cell shifts at CFL 1Constant homogeneous growth and integer cell travel at every step/output

The last row implements the constant-growth class of Inguva and Braatz (2023), Section 2.1, Eqs. 9–14. For this class it is also exact for bin averages. The special transformed meshes, separable variable growth and noncommuting split cases from later sections are not implemented yet. Fractional steps or incompatible output times raise an error rather than quietly interpolate. An integer multi-cell shift is equivalent to repeated exact one-cell substeps.

The methods cannot share a stable explicit time step and CFL=1 exact shifts on this fixed grid. The benchmark therefore declares method-appropriate steps and reports them. Accuracy-versus-cost curves are more informative than a fixed-grid speed ranking. Timing uses the minimum of three warmed forward solves, includes numerical factorization/setup and output copies, excludes Julia compilation and common model/initial construction. It measures this reference implementation on the recorded host, not a universal library ranking.

Measured smooth-case results at 128 × 128 bins (Julia 1.10.10, one thread, AMD EPYC 9V74; minimum of three warmed solves):

The compact variant is faster at this grid and chosen step, with a larger error. This is not an accuracy-matched speed claim. Its measured L1 refinement order from 64 to 128 bins is 3.967. All three conserve total number to roughly 5e-15 relative or better. Exact-shift precision applies to this eligible homogeneous class, not a general nucleating or coupled PBM.

For diagnostic comparison, positivity checks are disabled and both minimum density and negative particle number are recorded. Production simulation defaults to rejecting negative concentration. The compact scheme shows substantial undershoots on the rectangle; a claim of nonoscillatory behavior is unsupported. WENO has small undershoots too and still needs a proven positivity limiter. No state clipping is used.

solution_weno = simulate(problem;dt=0.4/n)
solution_compact = simulate(problem;method=HOCADI(time_order=4),dt=2/n)
solution_shift = simulate(problem;method=ExactShift(),dt=2/n)

Here problem is the eligible periodic constant-growth benchmark and n is its bins per axis. HOCADI and ExactShift are direct evolution methods selected by simulate. odeproblem(problem) exports the compiled residual (FV or moments), not those direct evolution methods.

Historical evidence and reproducibility

The figure and raw records below are the inherited benchmark evidence, recorded with Julia 1.10.10 on the host described in the environment file. Rerunning the script replaces the working benchmark CSVs and metadata. Times are host-dependent; compare errors, allocations, chosen steps, and output schedules together.

Full results CSV, environment, smooth cut, and rectangle cut preserve the recorded experiment.

At 128² bins the rectangle's minimum density was about $-0.30990$ for compact/ADI, $-1.6452\times10^{-7}$ for WENO, and zero for the eligible exact shift. The compact oscillations and negative number are part of the evidence. Diagnostic runs disable rejection to measure them; the default solver rejects negative states beyond tolerance and never clips them.

module PBM2DBenchmark
using PopulationBalanceModels

export problem,reference,run_benchmark
const VELOCITY=(0.5,0.25)
const FINAL_TIME=0.25
const PERIODIC=SizeBC(Periodic(),Periodic())

function _smooth_average(axis,t,velocity)
    L=last(axis.edges)-first(axis.edges)
    x=(axis.centers.-first(axis.edges).-velocity*t)./L
    n=length(axis)
    1 .+ 0.7*sinc(1/n).*cos.(2π.*(x.-0.2)) .+ 0.1*sinc(2/n).*cos.(4π.*(x.-0.2))
end
function _rectangle_average(axis,t,velocity)
    L=last(axis.edges)-first(axis.edges); a=first(axis.edges)+L/8+velocity*t; b=a+L/4
    [sum(max(0,min(axis.edges[i+1],b+k*L)-max(axis.edges[i],a+k*L)) for k in -2:2)/axis.widths[i] for i in 1:length(axis)]
end
function reference(g::Grid2D,t;profile=:smooth)
    average=profile===:smooth ? _smooth_average : profile===:rectangle ? _rectangle_average : throw(ArgumentError("unknown profile"))
    x=average(g.x,t,VELOCITY[1]); y=average(g.y,t,VELOCITY[2])
    (x*y').*(g.x.widths*g.y.widths')
end
function problem(n;profile=:smooth)
    # Unequal physical speeds and axis lengths prevent accidental cancellation
    # from assigning one speed (or their product) to both coordinate directions.
    g=Grid2D(range(0,1;length=n+1),range(0,0.5;length=n+1))
    op=compile(PBMModel(Growth2D(VELOCITY)),g;
        growth_scheme=WENO5(epsilon=1e-12),bc=SizeBC2D(x=PERIODIC,y=PERIODIC))
    PBMProblem(op,reference(g,0.0;profile),(0.0,FINAL_TIME))
end
function _metrics(prob,sol,truth)
    g=prob.operator.grid; area=g.x.widths*g.y.widths'; e=(sol.u[end].-truth)./area
    f=density(g,sol.u[end]); initial_number=sum(prob.u0)
    (;L1=sum(abs.(e).*area),L2=sqrt(sum(e.^2 .*area)),Linf=maximum(abs,e),
        relative_number_error=abs(sum(sol.u[end])-initial_number)/initial_number,
        minimum_density=minimum(f),negative_number=-sum(min.(sol.u[end],0.0)))
end
function run_benchmark(;grids=(32,64,128),profiles=(:smooth,:rectangle),repetitions=3,
        output=joinpath(@__DIR__,"..","docs","src","assets","results_2d.csv"))
    repetitions>=1 || throw(ArgumentError("repetitions must be positive"))
    rows=NamedTuple[]
    for profile in profiles,n in grids
        n%8==0 || throw(ArgumentError("use multiples of 8 for aligned exact output times"))
        prob=problem(n;profile); truth=reference(prob.operator.grid,FINAL_TIME;profile)
        profiles_at_final=Dict{String,Any}()
        # WENO uses an unsplit explicit CFL sum of 0.4. ADI/ExactShift use
        # directional CFL=1, which is not stable for the unsplit explicit method.
        for (label,method,dt) in (("WENO5_SSPRK33",SSPRK33(),0.4/n),
                ("HOCADI4_variant",HOCADI(time_order=4),2.0/n),
                ("InguvaBraatz_constant_shift",ExactShift(),2.0/n))
            solveit()=simulate(prob;dt,method,saveat=[FINAL_TIME],check_nonnegative=false)
            solveit() # JIT warmup, including the actual forward path
            times=Float64[]; bytes=Int[]; solution=nothing
            for _ in 1:repetitions
                sample=@timed solveit()
                push!(times,sample.time); push!(bytes,sample.bytes); solution=sample.value
            end
            metrics=_metrics(prob,solution,truth)
            profiles_at_final[label]=solution.u[end]
            row=merge((;profile=String(profile),n,method=label,dt,steps=solution.steps,
                seconds=minimum(times),allocated_bytes=minimum(bytes)),metrics)
            push!(rows,row)
            println(row)
        end
        if n==maximum(grids)
            g=prob.operator.grid
            # Cut through the pulse's interior at the final time.
            j=argmin(abs.(g.y.centers.-0.1875))
            mkpath(dirname(output))
            labels=("WENO5_SSPRK33","HOCADI4_variant","InguvaBraatz_constant_shift")
            open(joinpath(dirname(output),String(profile)*"_cut.csv"),"w") do io
                println(io,"x,exact,",join(labels,","))
                for i in 1:length(g.x)
                    area=g.x.widths[i]*g.y.widths[j]
                    println(io,join((g.x.centers[i],truth[i,j]/area,(profiles_at_final[label][i,j]/area for label in labels)...),","))
                end
            end
        end
    end
    mkpath(dirname(output))
    open(output,"w") do io
        println(io,join(string.(keys(first(rows))),","))
        for row in rows
            println(io,join(string.(values(row)),","))
        end
    end
    open(joinpath(dirname(output),"environment.txt"),"w") do io
        println(io,"PopulationBalanceModels ",Base.pkgversion(PopulationBalanceModels))
        println(io,"Julia ",VERSION,"; ",Sys.KERNEL," ",Sys.ARCH,"; threads=",Threads.nthreads())
        println(io,"CPU: ",Sys.cpu_info()[1].model)
        println(io,"Minimum of ",repetitions," warmed solves; numerical setup/factorization and output included; JIT/model construction excluded.")
    end
    rows
end

if abspath(PROGRAM_FILE)==@__FILE__
    run_benchmark()
end
end
